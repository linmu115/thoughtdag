# 会话图首次打开显示所属会话卡片

版本：dsh-thoughtdag 0.4.14-rc2.18。

用户在已完成会话的思维图中看到了空画布。独立数据端口的 ensure 原先只保存 ownerSessionId，却将 nodes 初始化为空；图确实属于会话，但没有该会话对应的卡片。

首次创建现在加入所属会话节点，节点身份为 session:<会话 ID>。宿主提供 sessionQuery 时尝试取得会话名称，否则标签使用会话 ID。图仍经 Core 会话扩展数据接口保存，DAG 不新增存储库，也不依赖 Maintenance。

为修复先前产生的空图，ensure 在同一 objectId 上补齐修订 1、没有节点和边且未归档的初始图。非空图、后续修订及归档图保持不变；用户之后主动移除卡片不会在每次打开时被强行恢复。重复打开不重复插入或增加修订。

20 项相关测试通过，包含首次创建、初始空图修复、保存后重开、已有布局和边保持、Core-only 宿主、写入许可和画布交互。实际部署和页面验收另记本次报告。

实际安装 .18 后，测试会话原修订 1 空图补齐为修订 2、1 张所属会话卡片、0 条连接。整页刷新并重新打开思维图后仍是同一修订和卡片；Maintenance 42831 无监听。此次只确认所属卡片和重开保持，未扩大为全部图业务验收。

待处理缺口：当前 0.1.5-rc.2 实例页面仍显示会话 ID，未取得原生会话标题“会话测试回复确认”。上述可选目录查询没有在本机得到标题；标题读取与跟随重命名需要单独核对宿主正式接口。没有将该显示缺口隐瞒为标题验收通过。


后续 .19：已用 rc.2 正式 readTitle/readTitleSnapshots 修复名称读取。图和会话节点在读取时显示当前标题，不增加修订、不改变图布局；实际测试会话已显示名称，后端核对仍为修订 2。此前名称缺口属于 .18 历史状态。完整 59 项串行测试、类型检查和构建通过。发布与新标签冷启动验证限制见 dsh/docs/RELEASE-20260920.md。
