# 会话贴纸从新建下游会话开始

来源：2026-09-19 用户在独立任务中提供五张截图，并明确回复“每次选择目标工作区”；选文所属会话为上游，新会话为下游，继承现有跨会话引用特性。此决定补充 [[DEC-selection-ownership-20260918]]，替代会话贴纸创建时优先选择已有会话的交互。

创建入口直接读取可创建工作区，不先加载贴纸总表或已有会话目录。选择工作区并确认后，核验固定来源版本和选区 occurrence，通过正式 create-session 创建空白会话，再调用 Core addCrossSessionReference，将引用放入新会话的待发送区。保存贴纸成功后通过原生 sessions.open 进入新会话；没有自动发送或模型调用。

X → Y 中，X 为来源，Y 为新建接收会话，关系属于 Y 的主干。沿用 Core / Maintenance 的固定版本、授权、继承、撤销与刷新规则，不引入第二套图关系。来源标记显示数字细圈，置于选文末端右上方；数字不因滚动出入视口而重新编号。

创建会话、登记引用和跳转分阶段；同次操作重试沿用原操作身份、已创建目标和固定来源。跳转失败重试不重复创建会话或贴纸。选文入口先完成本地回复身份检查，网络版本核验在用户确认创建时进行，消除进入选择页前重复的来源请求。

## 实现与验证

实现位于 SessionStickerPanel.tsx、宿主 client.js 和 host/source-marker-overlay.tsx。类型检查、构建、21 项来源标记测试、21 项主干/宿主/合成创建流程测试通过。合成流程覆盖正常创建、登记失败重试、跳转失败重试、无自动发送。真实实例外观和真实创建由用户验收。

## 开发历程草稿

先核对项目地图明确 X → Y 的归属，再移除旧贴纸列表和已有会话选择的前置加载。首版合成测试直接挂在顶层网页，触发已有的宿主身份保护；改成真实父子窗口的合成测试夹具后通过。没有放松生产代码的宿主校验。用户另行指定清理一张失效贴纸及三张测试贴纸，清理与源码部署分开，保留会话和正文。当前公开对话为来源，未绑定原始事件索引。

本任务不修改 BetterSidebar、多主窗口路由、Maintenance 服务或 Bridge 业务代码。安装保持当前实例其他插件，部署回执由本次 reference-polish-20260919 制品保存。
