# 上游拓扑绑定与关系边补齐

版本：dsh-thoughtdag **0.4.14-rc2.24**，目标 DSH 0.1.5-rc.2 / web profile。源码快照：分支 `codex/independent-plugins-20260920`，HEAD `547f9f7`，工作树干净。本轮 2026-09-21 五个提交：

| 提交 | 内容 |
|---|---|
| `132582a` | fix: 打开图时把已有授权关系补齐为画布边 |
| `595730c` | feat: 连线不再创建引用，改为上游拓扑绑定 |
| `8421341` | feat: 把图声明的上游支流告诉当前会话 |
| `6c715a6` | feat: 上游提示里带上来源会话 id |
| `547f9f7` | docs: 登记「上游绑定无法被模型自行读取」 |

## 一、修复「连线后没有产生边」

**问题**：画布上已经有 Core 授权关系，但图上没有对应的边。

**根因**：`importRelations`（把授权关系转成边）此前只被 `repairRelations()` 这条死代码调用，正常打开图的路径不会导入关系。

**改动**：`ManagedGraphApp.loadDocument` 现在会先 `await managedApi.relations(owner)`，再 `reconcileRelationEdges(...)` 调 `importRelations` 把关系落成边，并用 `sameEdges(left, right)` 保证幂等——边集合相同就不写 `importRelations`，避免每次打开都抬高文档修订。归档图（archivedAt）直接跳过。

## 二、连线语义改造

`beginConnect` 现在只做 `bindUpstream` + `persist`，随后提示「已绑定上游；未创建引用，也未读取内容」。同时删除了预览对话框、`ConnectionDraft` 类型、`confirmConnection` 和 `connection` state：连线不再预览来源、不再要求「已完成回复的固定上限」、不再调用 `attachReference`。代码注释写明了理由——绑定不能因为画了一条线就消耗上下文。

模型层：

- `EdgeKind` 增加 `'bound'`；`EDGE_LABELS.bound = '上游绑定'`。
- `bindUpstream(graph, source, target)` 写边 `bound:<source>:<target>`，`data = { kind: 'bound' }`；自连接、未知端点、重复绑定都返回原图（幂等）。
- `relationPresentation` 把无 `relationId` 的 `bound` 边呈现为 `{ state: 'knowledge', muted: false, dashed: true }`。
- 新增 `sameEdges(left, right)`，比较边列表的身份与全部 data 字段。

## 三、保存校验

`dsh/lib/session-graph.js` 保存时的授权核对改为只过滤 `edge.data.kind !== 'pending' && edge.data.relationId` 的边。绑定边没有 `relationId`，因此不会被这一步拦下。

## 四、模型可见的上游拓扑说明

`dsh/lib/managed-entry.js`：

- `inject` 增加 `systemPrompt`；`apply(ctx)` 末尾调用 `applyUpstreamContext(ctx)`。
- 该函数在 `systemPrompt.context()` 上注册名为 `thoughtdag:upstream-branches` 的动态上下文（`order: 10`），文本由 `upstreamNotice(data, assembly?.agent?.session?.id)` 生成。
- `upstreamNotice` 按 `graph-<sha256(sessionId)>` 找到当前会话的图，逐条列出绑定边与已有固定来源引用，格式为「<label>（<sourceSessionId>）→ 本会话（上游绑定：仅拓扑，未读取任何内容 | 已有固定来源引用）」。
- 边界文字明确写：这是拓扑信息不是内容授权、绑定不授予读取权限、`dsh_upstream_read` / `dsh_upstream_search` 只接受已提交引用的 `referenceId`。
- 没有绑定、没有图、图已归档或会话 id 缺失时返回空字符串，因此不占上下文。

## 五、发布与安装

`dsh/docs/INSTALL.md` 配套版本表列出 ThoughtDAG `0.4.14-rc2.24`（Core 为 0.3.12-rc2.26）。本机测试实例的 `profiles/web/node_modules/dsh-thoughtdag/package.json` 实际版本为 `0.4.14-rc2.24`，即该版本已安装到 profile web。本轮没有重启实例，也没有在浏览器里操作画布。

## 已核对但未修（必须如实登记）

1. **绑定边可能保存失败（本轮新发现，未修）**：`dsh/lib/session-graph.js` 的 `validateSessionGraph` 第 23 行仍要求每条边的 `data.kind` 属于 `['pending', 'upstream', 'branch']`，而 `bound` 不在其中；实测传入带 `bound` 边的合法图会抛「图连接必须表达上下文授权」。保存路径 `save()` 第一行就调用它，因此「保存校验放宽」只放宽了按 `relationId` 的授权核对，**没有**放宽边类型白名单。绑定边能否真正落盘需要下一轮确认（要么放行 `bound`，要么在提交流程里转换）。
2. **上游绑定对模型不可读（未修，待定方案）**：绑定是纯拓扑，不带锚点、不授权。DSH 的原生 `ctx.sessionQuery` 能按会话 id 读，但它是 Cordis 服务、不是模型工具；模型唯一可见的跨会话读取工具 `dsh_upstream_read` / `dsh_upstream_search` 只接受已提交引用的 `referenceId`。是否由插件注册一个 `upstreamRead` 风格工具（读取范围、起点、上限、审计回执四项都待定）尚未与用户确认，本轮不实施。详见 `dsh/README.md` 的同名已知问题。
3. **打开贴纸对象跳转失败（未修）**：DAG 向宿主 `resolve` 发送 `logicalSessionId`，宿主校验要求二选一且严格，两条分支都失败；注释对象那条路径已改用 `nativeSessionId`，贴纸这条漏了。代码位置：`dsh/lib/client.js` 的 `open-object` 分支（第 204 行附近用 `resolve?logicalSessionId=…`），而宿主解析入口要求 `nativeSessionId`（同文件第 168、170 行）。已发布的 r23 预览包里也把这条记为「打开贴纸对象跳转失败（未修复）」：`artifacts/architecture-upgrade-20260920/independent-preview-r23/dag-README.md`（该文件里这条标题在第 45 行），可以作为发布侧的一致记录。
